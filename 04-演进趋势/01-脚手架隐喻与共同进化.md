# 脚手架隐喻与共同进化

## 什么是脚手架隐喻？

建筑工地上，脚手架是**临时基础设施**——它帮助工人完成施工，大楼建成后就会被拆除。

**Agent Harness 也是如此**：它是让模型落地为智能体的**临时支撑**。

```
  建筑领域                       AI 领域
┌────────────┐            ┌────────────────┐
│  大楼       │            │  智能体能力      │
│  (最终成果) │            │  (任务成功率)    │
├────────────┤            ├────────────────┤
│ 脚手架      │            │  Agent Harness  │
│  (临时支撑) │            │  (临时基础设施)  │
├────────────┤            ├────────────────┤
│ 工人        │            │  大语言模型      │
│  (施工者)   │            │  (能力来源)      │
└────────────┘            └────────────────┘
```

**核心命题：模型能力越强，Harness 的复杂度就应该越低。**

## 共同进化规律

### 为什么 Harness 会越来越薄？

现代大模型的演进路径与 Harness 深度耦合：

1. **后训练阶段纳入 Harness**：模型在后训练（post-training）时，会把特定 Harness 纳入训练循环——模型在训练中就「学会」了在 Harness 环境里如何表现；
2. **模型与框架深度耦合**：模型内化 Harness 的行为模式（如何调用工具、如何遵循系统提示、如何组织推理），成为模型能力的一部分；
3. **模型内化的能力越多 → Harness 需要的封装就越少**。

> 也就是说：过去靠 Harness「手把手教」模型做的事（如严格格式化工具调用），随着模型变强，变成了模型「天生就会」——脚手架自然可以拆掉。

### 案例验证：Manus 半年五次重构，全部做减法

Manus 项目在**半年内重构五次**，每一次都在**做减法**：

| 调整 | 方向 |
| --- | --- |
| 将复杂的工具定义简化为通用 Shell 执行 | 减少特殊化封装 |
| 将管理智能体简化为结构化交接 | 减少层次与开销 |
| ……（持续精简） | 整体向薄演进 |

**结果：性能反而持续提升。**

> 反直觉的结论：删掉 Harness 的复杂度，性能不降反升——因为模型已经足够强，多余的脚手架只是负担。

## 面向未来的测试（Future-proof Test）

一个优秀的 Harness 设计，必须通过**面向未来的测试**：

> **模型升级后，智能体性能自然提升，无需增加 Harness 复杂度。**

### 具体含义

- **通过**：换更强的模型，同样的 Harness 直接变强——说明 Harness 是「放大器」，没有成为模型能力的瓶颈；
- **失败**：换更强的模型，性能没提升甚至下降——说明 Harness 的设计「帮了倒忙」，把模型的能力限制住了（如上下文管理过激压缩、工具集过窄、流程锁死过死）。

### 为什么这个测试重要？

- Harness 是要长期演进的基础设施，而模型每 6-12 个月就升一代；
- 如果 Harness 跟不上模型升级，就会成为**负资产**；
- 面向未来测试的本质：**验证 Harness 是「可进化的脚手架」而不是「永久性囚笼」**。

## 行业趋势：更薄的 Harness、更强的模型、更模块化的架构

| 趋势 | 含义 |
| --- | --- |
| **更薄的 Harness** | 信任模型，减少不必要的封装与流程控制 |
| **更强的模型** | 推理、工具调用、长上下文等能力继续内化进模型 |
| **更模块化的架构** | Harness 组件可独立替换、独立演进（呼应十二模块的独立可替换性） |

## 思考与原则

### 1. 什么时候该「加厚」Harness？

模型还不够强、任务风险极高、需要确定性流程的场景。Harness 的厚度应与「模型信任度」匹配：信任不够，就得靠厚 Harness 兜底。

### 2. 什么时候该「减薄」？

模型已证明可靠、任务允许自主决策、迭代成本敏感的场景。每多一层封装，都是延迟、成本和复杂度。

### 3. 减薄不是简单删代码

- 减薄的依据是「模型已经内化了什么能力」，而不是「想删就删」；
- 删掉一个模块前，先做面向未来测试：模型升级后，少了它真的没事吗？

### 4. Harness 与模型是共同设计

- 模型厂商在后训练阶段纳入 Harness 范式；
- Harness 开发者顺应模型能力做减薄；
- 两者互相塑造——这正是「共同进化」的含义。

## 小结

| 维度 | 要点 |
| --- | --- |
| 隐喻 | Harness 是脚手架，大楼建成即拆除 |
| 规律 | 模型能力越强 → Harness 越薄 |
| 机制 | 后训练纳入 Harness → 模型内化 → 封装减少 |
| 案例 | Manus 半年五重构全做减法，性能反升 |
| 测试 | 面向未来测试：模型升级后 Harness 无需加厚也能变强 |
| 趋势 | 更薄 Harness + 更强模型 + 更模块化架构 |
