# 抉择 3：上下文管理策略

## 问题

上下文是稀缺资源，怎么管理？行业里有五种方法，各有取舍。

## 五种策略一览

| # | 策略 | 机制 | 优势 | 风险 |
| --- | --- | --- | --- | --- |
| 1 | **基于时间清理** | 超过 N 轮/N 时间的历史直接丢弃 | 实现最简单 | 可能丢掉关键决策依据 |
| 2 | **对话摘要** | 对历史做摘要，保留核心、丢弃冗余 | 显著省 token | 摘要会失真、丢细节 |
| 3 | **观察掩码** | 隐藏旧工具输出细节，保留工具调用记录 | 保留逻辑链，省 token | 细节不可再查（除非配检索） |
| 4 | **结构化笔记** | 把对话整理成结构化笔记（决策、待办、结论） | 高信噪比、可检索 | 需要额外的整理机制 |
| 5 | **子智能体委派** | 复杂任务交给子智能体，只回传精简摘要 | 大幅降低主上下文压力 | 调度复杂、有通信开销 |

## 核心原则：保留推理痕迹，减少 Token 消耗

五种策略看似各异，共享同一个核心原则：

> **保留推理痕迹（reasoning trail），减少 Token 消耗。**

- **保留什么**：决策、未解决问题、工具调用逻辑链——这些是任务继续的前提；
- **减少什么**：冗余工具输出、过时中间过程、重复信息——这些是纯噪音；
- 两条线同时做：该留的留全，该省的省光。

## 逐策略展开

### 1. 基于时间清理

- 最简单：设一个窗口（如最近 20 轮），窗口外的直接不要；
- 适用：短任务、对历史依赖低的场景；
- 风险：早期关键决策可能被误删——只能作为兜底策略。

### 2. 对话摘要

- 用模型/规则对历史生成摘要，保留「核心决策 + 未解决问题」；
- 模块 4 中「压缩（Compaction）」的落地方式；
- 风险：摘要即失真——每次压缩都在损失细节，需保留原始记录以备回溯。

### 3. 观察掩码

- 隐藏旧工具输出细节（结果太长），但保留「调过什么工具、调用顺序」；
- 模块 4 中「观察屏蔽」的落地方式；
- 价值：工具调用记录是任务逻辑链的骨架，丢了它模型就无法理解「现状怎么来的」。

### 4. 结构化笔记

- 不依赖原始对话，而是维护一份「结构化笔记」：当前目标、已完成、待办、关键决策；
- 模型主要读笔记而非原始历史——信噪比最高；
- Claude Code 的进度文件（模块 7）就是这个思路的体现；
- 注意：笔记本身也需要维护机制（谁更新、什么时候更新、冲突怎么办）。

### 5. 子智能体委派

- 把复杂探索/执行交给子智能体，主智能体只接收 1000-2000 Token 摘要；
- 模块 4 策略四 + 模块 11 的落地方式；
- 收益：主上下文保持精简，适合大型任务；
- 代价：子智能体的上下文是「额外成本」，且协调有开销。

## 怎么组合使用？

生产级系统很少只用一种，通常是分级防线：

```
第 1 道：结构化笔记（常驻，最高信噪比）
第 2 道：观察掩码（工具结果按需精简）
第 3 道：对话摘要（接近上限时压缩历史）
第 4 道：子智能体委派（大型任务，从源头减负）
第 5 道：基于时间清理（兜底，绝不让上下文溢出）
```

## 思考与原则

1. **先设计再兜底**：好的上下文管理在设计阶段就控制信息流入（最小必要原则），清理只是兜底；
2. **可回溯是底线**：无论怎么压缩，原始记录要能检索——「压缩」不等于「删除」；
3. **策略要可观测**：记录每次压缩/屏蔽/委派发生的时间、对象、省了多少 token，用数据调参；
4. **与记忆系统配合**：上下文管理管「本次运行」，长期知识归记忆模块，分工清晰。

## 决策速查

| 你的情况 | 推荐组合 |
| --- | --- |
| 短任务、上下文宽裕 | 不管理（或基于时间清理兜底） |
| 中长对话 | 对话摘要 + 观察掩码 |
| 复杂长任务 | 结构化笔记 + 子智能体委派 |
| 生产级系统 | 五层组合，分级防线 |

## 小结

| 维度 | 要点 |
| --- | --- |
| 五种策略 | 时间清理 / 对话摘要 / 观察掩码 / 结构化笔记 / 子智能体委派 |
| 核心原则 | 保留推理痕迹，减少 Token 消耗 |
| 组合思路 | 分层防线，先设计再兜底 |
| 底线 | 可回溯：压缩 ≠ 删除 |
