# 抉择 4：验证循环设计

## 问题

验证是生产级智能体的分水岭。但验证怎么设计？行业把验证分成两大类：**计算式验证**与**推理验证**，两者结合最优。

## 两大类验证的对比

| 维度 | 计算式验证（Deterministic） | 推理验证（Inference-based） |
| --- | --- | --- |
| 手段 | 测试用例、Linter、类型检查器等确定性工具 | 让模型当裁判，评估语义与逻辑 |
| 判定 | 可复现、客观、无歧义 | 主观、语义化、可能有偏差 |
| 速度 | 快 | 慢（要跑模型） |
| 成本 | 低 | 高（额外 token/算力） |
| 覆盖 | 规则可表达的部分 | 规则表达不了的部分（语义、逻辑、质量） |

## 为什么必须两者结合？

单一验证方式都有致命盲区：

- **只用计算式验证**：能确认「代码语法对、测试过」，但确认不了「报告结论是否有道理、方案是否真正解决了用户问题」；
- **只用推理验证**：裁判模型可能「自信地误判」——没有确定性工具兜底，语义判断就成了空中楼阁。

**结论：计算式验证提供确定性底线，推理验证处理语义问题——两者互补，缺一不可。**

## 计算式验证详解（提供确定性）

| 工具 | 验证什么 | 例子 |
| --- | --- | --- |
| 测试用例 | 行为是否符合预期 | 函数输入输出断言 |
| Linter | 代码风格与静态问题 | 未使用变量、语法错误 |
| 类型检查器 | 类型一致性 | TypeScript/Python 类型错误 |
| Schema 校验 | 数据结构合法性 | JSON 是否符合定义 |
| 编译/构建 | 能否构建成功 | CI 流水线 |

> 计算式验证的价值：**确定性**——同样的输入永远得到同样的判定，结果可复现、可审计、无幻觉。

## 推理验证详解（处理语义）

| 手段 | 验证什么 | 例子 |
| --- | --- | --- |
| 模型裁判 | 语义、逻辑、效果 | 报告是否有数据支撑、结论是否自洽 |
| 评估子智能体 | 按评分卡评估输出质量 | 文案是否符合品牌调性、回答是否遗漏关键点 |
| 对比验证 | 与期望结果对比 | 方案是否满足用户全部要求 |

> 推理验证的价值：**语义覆盖**——能判断「好不好、对不对、全不全」，这是确定性工具做不到的。

## 验证循环的正确设计

验证不是「一次检查」，而是一个**闭环**：

```
模型输出
   │
   ▼
计算式验证（快、确定性）─── 失败 → 反馈给模型修正 → 重新输出
   │ 通过
   ▼
推理验证（慢、语义）────── 不达标 → 反馈给模型修正 → 重新输出
   │ 达标
   ▼
交付 / 进入下一步
```

### 关键设计点

1. **先快后慢**：先跑廉价的计算式验证，通过再跑昂贵的推理验证；
2. **失败要反馈**：验证失败详情要回传给模型（哪步错了、期望什么），让它修正而不是瞎猜；
3. **设定修正上限**：达到重试上限仍失败，如实交付「未验证通过」或请用户介入（呼应错误处理模块的重试限制）；
4. **验证结果要留痕**：每次验证的输入、结果、修正次数都要记录，这是可信度证据链。

## 数据支撑：验证的价值

> Claude Code 创始人鲍里斯·切尔尼：给智能体加入验证自身工作的机制，能让**输出质量提升 2 到 3 倍**（模块 10 详述）。

## 思考与原则

### 1. 别用推理验证替代计算式验证

- 模型裁判再聪明，也不如一个单元测试确定；
- 能写成规则验证的，绝不交给模型——省 token、省延迟、还更可靠。

### 2. 裁判要「隔离 + 评分卡」

- 裁判子智能体与主智能体上下文隔离（避免共谋式自我认可）；
- 裁判要有明确评分标准，而不是泛泛「你觉得如何」。

### 3. 验证密度按风险调节

| 风险等级 | 验证强度 |
| --- | --- |
| 低（闲聊、草稿） | 轻验证或跳过 |
| 中（代码、数据） | 计算式验证为主 |
| 高（支付、外发、生产变更） | 全链路验证 + 人在环上 |

## 决策速查

| 你的场景 | 验证方案 |
| --- | --- |
| 代码/配置/格式 | 计算式验证（测试/Linter/类型检查） |
| 语义/逻辑/质量 | 推理验证（模型裁判） |
| 生产级系统 | 计算式 + 推理式结合，先快后慢 |
| 高风险操作 | 全链路验证 + 人工确认 |

## 小结

| 维度 | 要点 |
| --- | --- |
| 两类验证 | 计算式（确定性）/ 推理式（语义） |
| 结合原则 | 计算式提供底线，推理式处理语义，缺一不可 |
| 循环设计 | 先快后慢、失败反馈、修正上限、结果留痕 |
| 效果 | 验证机制让输出质量提升 2-3 倍 |
