# Agent Harness 完全指南

> 基于一份 AI 结构化知识文档。目标是让读者理解：**Agent Harness 是什么、为什么需要它、它由哪些模块构成、主流框架如何落地、未来走向何方、以及搭建时要做什么架构抉择。**

## 这套文档讲什么

2026 年，全球 AI 社区的竞争焦点已经从「模型参数内卷」转向「Harness 工程较量」。Anthropic、OpenAI、LangChain、Perplexity 等团队都在疯狂加码这个赛道。这套文档把「Agent Harness」这一概念完整拆解：

- 为什么智能体「演示流畅、生产翻车」的根因不是模型，而是基础设施；
- Harness 的定义、本质与计算机架构类比；
- 一个生产级 Harness 必须有的**十二大核心模块**；
- 五大主流框架（Anthropic / OpenAI / LangGraph / CrewAI / AutoGen）如何落地；
- 脚手架隐喻与「模型越强 Harness 越薄」的共同进化规律；
- 搭建 Harness 必须面对的**七大架构抉择**。

- **标注**：展开中的通用技术解释（如 MCP、Pydantic、冯·诺依曼架构）属于常识性补充，用于降低阅读门槛。

## 核心速览（30 秒版）

1. **痛点**：智能体演示流畅、生产翻车——根因是模型周围的基础设施（Harness），不是模型；
2. **证据**：LangChain 不改模型只改 Harness，评测从 30 名外到第 5；LLM 自主优化 Harness 通过率 76.4%；
3. **定义**：Harness = 包裹 LLM 的操作系统级基础设施，把裸模型变成有目标、会用工具、能纠错、可持久运行的智能体；
4. **骨架**：十二大核心模块——编排循环 / 工具 / 记忆 / 上下文管理 / 提示词组装 / 工具调用与结构化输出 / 状态检查点 / 错误处理 / 护栏 / 验证反馈 / 子Agent编排 / 初始化环境；
5. **框架**：Anthropic（薄、信任模型）、OpenAI（代码优先）、LangGraph（显式图）、CrewAI（角色团队）、AutoGen（对话驱动）；
6. **规律**：模型越强，Harness 越薄——Harness 是脚手架，不是囚笼；
7. **抉择**：单 vs 多智能体、ReAct vs 计划-执行、上下文策略、验证设计、权限安全、工具范围、Harness 厚度。
