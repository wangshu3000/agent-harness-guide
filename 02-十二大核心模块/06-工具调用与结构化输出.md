# 模块 6：工具调用与结构化输出（Tool Calling & Structured Output）

## 一句话定位

**工具调用与结构化输出是模型与 Harness 之间的通用语言**，解决了传统自由文本输出难以解析、容易出错的问题。

## 为什么需要这门「通用语言」？

早期智能体让模型用自然语言描述「我要调用某个工具」，然后 Harness 解析文本：

- 模型措辞稍有变化，解析就失败；
- 参数传递模糊，容易缺参、错参；
- 解析错误率高，整个流程不可靠。

现代生产级 Harness **完全依赖原生工具调用**：模型不再输出模糊的自然语言指令，而是直接返回标准化的 `tool_calls` 结构化对象。

## 核心机制：原生工具调用（Native Tool Calling）

模型输出是一个结构化对象，包含明确信息：

```json
{
  "tool_calls": [
    {
      "name": "search_web",
      "arguments": {"query": "Agent Harness 2026 趋势", "limit": 5}
    }
  ]
}
```

- **工具名称**：明确要调用哪个工具；
- **参数值**：结构化、类型明确，无需解析。

### 判断逻辑变得极其简单

有了结构化输出，Harness 的判断逻辑就从「解析自然语言」简化为：

```
解析模型输出
├─ 存在工具调用 → 执行对应工具，继续循环
└─ 没有工具调用 → 直接将模型输出作为最终答案，终止循环
```

### 为什么这很重要？

- **零解析歧义**：结构化对象天然机器可读；
- **错误前置**：参数类型错误在校验层就能拦截；
- **循环判定清晰**：编排循环（模块 1）的终止判断有了明确依据。

## 结构化输出：Schema 约束

对于「不调工具、直接输出答案」的场景，同样需要结构化约束：

- **OpenAI 与 LangChain** 都支持通过 **Pydantic** 框架进行 Schema 约束；
- 定义输出模型（如 `class 报告(BaseModel): 结论: str; 置信度: float`），模型输出必须符合该结构；
- **收益**：确保输出格式符合预期，降低下游解析失败率，让结果可直接进数据库/前端/下一个流程。

### 补充理解 Pydantic

Pydantic 是 Python 生态最流行的数据校验库：用类型注解声明数据结构，自动完成校验、序列化、类型转换。在智能体里，它同时承担「工具参数 Schema」和「输出 Schema」的定义职责，是结构化输出的基础设施。

## 遗留方案：RetryWithErrorOutputParser

一些**遗留方案在边缘场景仍然有用**，典型代表是 `RetryWithErrorOutputParser`：

- **流程**：模型输出解析失败时，把 **原始提示词 + 失败输出 + 解析错误** 一并返回给模型，让模型自主修正后重新解析；
- **本质**：把「解析失败」当作一次可恢复错误，用模型自身能力自愈；
- **局限**：效率较低——每失败一次就多一轮推理，浪费 token 与延迟；
- **定位**：只建议作为**补充方案**，主路径应依赖原生工具调用与 Schema 约束。

## 设计原则与思考

### 1. 主路径用原生，兜底用重试解析

- 主路径：原生 `tool_calls` + Pydantic Schema 约束（高可靠、高效率）；
- 兜底：RetryWithErrorOutputParser 这类自愈解析（低频率边缘场景）。

### 2. 参数校验不能只靠模型自觉

- Schema 校验（模块 2 工具层）必须在执行前强制做；
- 模型可能传错类型、漏传必填项、甚至编造不存在的参数。

### 3. 结构化输出让下游「零心智负担」

- 输出结构化的最终目的是：让结果可以被程序直接消费；
- 定义 Schema 时要以「下游怎么用」为准，而不是「模型怎么方便」。

## 常见问题

### Q1：模型返回了非法工具调用怎么办？

拒绝执行 + 把错误信息（如「参数 x 类型应为 int」）作为工具结果回传给模型，让它自我修正——这是错误处理模块（模块 8）的「模型可恢复错误」路径。

### Q2：结构化输出会不会限制模型能力？

会，但这是有意的约束。结构化牺牲了表达的灵活性，换取了系统的确定性。需要自由表达的环节（如创意文本）可以走非结构化输出，工具调用与数据结果走结构化——按场景分流。

## 小结

| 维度 | 要点 |
| --- | --- |
| 角色 | 模型与 Harness 的通用语言 |
| 主机制 | 原生 tool_calls 结构化对象 |
| 输出约束 | Pydantic Schema（OpenAI/LangChain） |
| 遗留兜底 | RetryWithErrorOutputParser（低效，仅边缘用） |
| 设计原则 | 主路径结构化、校验前置、输出面向下游 |
