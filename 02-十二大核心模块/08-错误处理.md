# 模块 8：错误处理（Error Handling）

## 一句话定位

**错误处理是智能体在复杂环境中稳定运行的安全网。** 没有它，任何一次小错误都可能滚成雪球，最终导致任务彻底失败。

## 残酷的数学事实：错误会滚雪球

很多人忽视一个数学事实：

> 一个 **10 步**的任务流程，即便每一步成功率高达 **99%**，端到端的总成功率也只有：
>
> 0.99¹⁰ ≈ **90.4%**

如果任务有 30 步：0.99³⁰ ≈ **74%**。如果每步成功率是 95%（真实环境很常见）：
- 10 步：约 60%；
- 30 步：约 21%。

**结论**：长任务 + 高失败概率 = 必然失败。错误会像滚雪球一样不断放大——一步失败，后续步骤全基于错误的前提继续执行，越错越远。

### 这意味着什么？

1. 生产级智能体不能假设「模型一次成功」；
2. 必须有分层、分类的错误处理机制，把单点失败「就地消化」，而不是任其传染整条任务链。

## LangGraph 的行业典范：四类错误分类与处理

LangGraph 的错误处理设计堪称行业典范，它把错误分成四类，每类对应不同策略：

| 错误类型 | 典型例子 | 处理策略 | 类比 |
| --- | --- | --- | --- |
| **瞬时错误** | 网络波动、API 限流 | 带**退避策略**的重试机制 | 网络重连 |
| **模型可恢复错误** | 参数错误、逻辑失误 | 将错误**包装成工具消息返回给模型**，让模型自主调整 | 让员工自己改 |
| **用户可修复错误** | 权限不足、配置错误 | 通过**中断流程等待人工输入** | 上报领导 |
| **意外错误** | 系统崩溃、底层异常 | **直接抛出错误**，便于调试 | 崩溃报告 |

### 为什么按类处理，而不是统一重试？

- 统一重试对瞬时错误有效，但对逻辑错误只会重复失败（浪费资源）；
- 模型可恢复错误是智能体独有的机会：模型能「看懂」错误信息并自我修正，这是传统软件没有的能力；
- 用户可修复的错误不该自动化硬闯（权限问题重试 100 次也没用）；
- 意外错误要「显性失败」，掩盖反而延误排障。

## Anthropic 的策略：流程稳定性优先

- **在工具处理器内部捕获所有失败**；
- 将错误结果**返回给模型**（作为工具结果消息）；
- **确保主编排循环不中断**。

### 设计意图

- 主循环（模块 1）是「笨循环」，不该被工具异常打断；
- 错误被「包装成正常消息」回传，模型在下轮推理里自然处理；
- 这本质上是把「模型可恢复错误」作为**默认路径**，最大程度保证流程连贯。

## Stripe 的保守策略：限制重试次数

Stripe 的生产级 Harness 则更**保守**：

- 将重试次数**严格限制在两次以内**；
- 目的：**避免无限重试引发的资源耗尽**。

### 为什么需要限制？

- 无限重试 = 无限消耗 token、算力、时间、外部 API 配额；
- 失败的任务早该失败，拖着只会放大成本；
- 重试上限 + 优雅降级（给出部分结果/明确失败）是生产系统的成熟形态。

## 设计原则与思考

### 1. 错误必须「分类」而非「一锅端」

按「可重试/可自愈/需人工/需崩溃」四类分诊，是错误处理的起点。

### 2. 错误信息要「模型友好」

既然要让模型自我修正，错误信息就必须写清楚：发生了什么、为什么失败、期望是什么。模糊的错误信息只会让模型瞎猜。

### 3. 重试要带退避（Backoff）

瞬时错误（限流、网络）立即重试大概率再失败。指数退避 + 抖动（jitter）是标准做法。

### 4. 失败要可观测

每个错误的分类、重试次数、最终结果都要有日志——「错误被消化了」和「错误被掩盖了」必须可区分。

### 5. 与验证循环（模块 10）配合

错误处理管「执行期失败」，验证循环管「执行成功但结果不对」。两者构成完整的质量防线。

## 常见问题

### Q：什么时候该让用户介入？

权限不足、配置错误、需要业务决策——这类「用户可修复错误」应中断等待，而不是让智能体硬闯或静默降级。

### Q：重试和退避的参数怎么设？

经验起点：最大重试 2-3 次、指数退避（1s/2s/4s）+ 随机抖动、总超时上限。具体按外部服务 SLA 调。

## 小结

| 维度 | 要点 |
| --- | --- |
| 数学事实 | 99% 的单步成功率，10 步后只剩 90.4% |
| 四类分诊 | 瞬时（重试）/ 模型可恢复（回传自愈）/ 用户可修复（中断）/ 意外（抛出） |
| Anthropic | 工具处理器内捕获，包装成消息回传，主循环不中断 |
| Stripe | 重试 ≤2 次，防止资源耗尽 |
| 原则 | 分类处理、模型友好报错、退避重试、失败可观测 |
