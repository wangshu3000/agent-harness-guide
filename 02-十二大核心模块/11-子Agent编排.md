# 模块 11：子 Agent 编排（Subagent Orchestration）

## 一句话定位

**子 Agent 编排可以让单个智能体升级为智能体集群**，从而解决复杂、大规模、多领域的任务需求。

## 什么时候需要子 Agent？

单个智能体（一个模型 + 一套上下文 + 一个循环）并非万能的，当出现以下情况时，性能会大幅下降：

| 触发条件 | 为什么单智能体撑不住 |
| --- | --- |
| 任务涉及多个专业领域 | 一个上下文要同时装下多个领域的知识，互相干扰 |
| 工具数量过多 | 工具清单过长，模型选择困难（参见架构抉择篇《工具范围》） |
| 流程过于复杂 | 单循环内步骤太多，上下文膨胀、错误累积 |
| 信息量过大 | 全部塞进一个上下文，必然触发上下文腐烂 |

这时，**子 Agent 编排就是最优解**：把大任务拆成多个小任务，交给各自独立上下文、独立循环的子智能体并行/分治处理，主智能体只负责调度与汇总。

## 核心思路：上下文隔离 + 结果精简

子 Agent 编排的价值来自两个机制：

1. **上下文隔离**：每个子 Agent 有自己的上下文窗口，互不污染——主智能体不用背着所有细节；
2. **结果精简**：子 Agent 只返回精简摘要（1000–2000 Token），大幅降低主智能体的上下文压力（呼应模块 4 的策略四）。

## 三大主流框架的实现方案

### 1. Claude Code：三种执行模式

| 模式 | 机制 | 适用 |
| --- | --- | --- |
| **Fork 模式** | 创建父上下文的**精确副本**，子任务基于副本独立推进 | 需要完整继承父上下文的任务 |
| **Teammate 模式** | 通过**独立终端面板**通信，多个智能体并行协作 | 需要实时协作、信息交换 |
| **Worktree 模式** | 为每个 Agent 分配**独立 Git 工作树**，代码空间隔离 | 并行开发互不干扰，靠 Git 合并 |

### 2. OpenAI Agents SDK：两种模式

| 模式 | 机制 | 适用 |
| --- | --- | --- |
| **Agents-as-tools** | 专家 Agent 作为「工具」被主 Agent 调用，处理细分任务 | 子任务是可独立完成的专业环节 |
| **Handoffs（交接）** | 任务**全面交接**：主 Agent 把控制权交给另一个 Agent | 需要换角色/换技能来继续任务的场景 |

> 理解区别：Agents-as-tools 是「调用后拿结果回来」（主 Agent 保持控制）；Handoffs 是「交出去就不管了」（控制权转移）。

### 3. LangGraph：嵌套状态图

- 将子 Agent 实现为**嵌套状态图**（nested state graph）；
- 主图的一个节点，内部是一张完整的子图（有自己的节点、边、状态）；
- 通过**图结构**管理任务流转，层次清晰、可调试。

## 设计原则与思考

### 1. 拆分的依据：任务域与工具集

- 任务域明显分离（如「调研」与「写作」）、工具集重叠少，才值得拆；
- 单纯「任务长」不是拆分的理由——拆分会带来调度、通信、协调开销（详见架构抉择篇《单智能体还是多智能体》）。

### 2. 结果要「摘要化」

- 子 Agent 返回给父级的应是**结论与要点**，不是完整过程；
- 摘要粒度（1000–2000 Token 是经验值）要控制好：太少丢信息，太多压垮父上下文。

### 3. 通信协议要明确

- 子 Agent 之间的依赖关系（谁等谁、结果怎么传）要在编排层定义清楚；
- 并行子任务可并发执行，串行依赖要显式建模（呼应 LangGraph 的图结构）。

### 4. 子 Agent 也要被治理

- 子 Agent 不是「法外之地」：护栏、错误处理、验证在子层级同样要生效；
- 子 Agent 的失败必须能上抛给父级处理，不能静默吞掉。

## 常见问题

### Q：子 Agent 越多越好吗？

不是。多智能体有额外开销：上下文复制、通信、协调、失败传播。行业共识是「先榨干单智能体性能」，只有工具重叠超 10 个或任务域明显分离时才考虑拆分。

### Q：子 Agent 共享记忆还是隔离记忆？

默认隔离。子任务上下文独立是子 Agent 的价值所在；需要共享的信息（如项目全局约定）通过「初始化时注入」或「结果汇总」实现，而不是让所有子 Agent 共享一个上下文。

## 小结

| 维度 | 要点 |
| --- | --- |
| 角色 | 单智能体 → 智能体集群 |
| 触发条件 | 多领域、工具过多、流程复杂、信息量大 |
| 核心机制 | 上下文隔离 + 结果精简 |
| Claude Code | Fork / Teammate / Worktree 三模式 |
| OpenAI | Agents-as-tools（拿结果）/ Handoffs（交控制权） |
| LangGraph | 嵌套状态图 |
| 原则 | 按任务域拆分、摘要化返回、明确通信、子级同样受治理 |
