# 模块 10：验证与反馈（Verification & Feedback）

## 一句话定位

**验证与反馈是玩具级智能体和生产级智能体的分水岭。** 没有验证的智能体，输出结果永远不可信。

## 为什么是「分水岭」？

- 玩具 Demo：模型输出什么，人就信什么；
- 生产智能体：**模型说完成了，不等于真的完成了**。

没有验证环节，可能出现：

- 模型说「文件已保存」，实际保存失败；
- 模型说「测试全部通过」，实际没跑测试；
- 模型自信地给出错误结果，无人发现。

## 三大行业通用验证方式

Anthropic 推荐了三种行业通用的验证方式，覆盖「确定性」与「语义性」两类问题：

### 方式 1：基于规则的反馈（确定性验证）

- **手段**：测试用例、Linter 代码检查、类型检查器等**确定性工具**；
- **原理**：用「非模型」的规则去核对「模型输出」，结果是可复现、可判定的；
- **示例**：写完代码跑单元测试；改完配置跑 schema 校验；生成 JSON 后做格式校验；
- **优点**：确定、快速、无幻觉；
- **局限**：只能验证「规则可表达」的部分，无法判断「语义是否合理」。

### 方式 2：视觉反馈（视觉验证）

- **手段**：借助 **Playwright** 等工具**截图**，检查 UI 任务或可视化操作的完成效果；
- **原理**：让「屏幕上的真实状态」成为验证依据，而不是模型的自述；
- **示例**：智能体做了个网页改动 → 截图 → 检查元素是否按预期渲染；
- **优点**：能验证「视觉层面」的完成度，是 UI 类任务的刚需；
- **局限**：需要可访问的运行环境，且截图本身需要人工/模型解读。

### 方式 3：模型当裁判（推理验证）

- **手段**：用**独立的子智能体**评估主智能体的输出；
- **原理**：让「另一个视角」从语义、逻辑和效果等维度给出反馈——自己检查自己容易自我美化；
- **示例**：主智能体写了一份分析报告，裁判智能体检查「结论是否有数据支撑、逻辑是否自洽、有无遗漏」；
- **优点**：能验证语义、逻辑、质量等「规则无法表达」的维度；
- **局限**：裁判也是模型，可能有偏差；需设计好裁判的评估标准。

### 三种方式怎么选？

| 验证目标 | 首选 | 补充 |
| --- | --- | --- |
| 代码/配置/格式是否正确 | 规则反馈（测试、Linter、类型检查） | — |
| UI 是否按预期呈现 | 视觉反馈（截图） | 模型裁判 |
| 语义、逻辑、质量是否达标 | 模型裁判 | 规则反馈 |
| 生产级完整方案 | 三者组合：确定性优先，语义性兜底 | — |

## 硬核数据：验证能让输出质量提升 2-3 倍

> Claude Code 的创始人鲍里斯·切尔尼（Boris Cherny）明确指出：
> **给智能体加入验证自身工作的机制，能让输出质量提升 2 到 3 倍。**

### 为什么提升这么大？

- 验证让模型「知道自己错了」→ 才有机会「改对」；
- 没有验证，错误会「自信地」一路传播到最终交付；
- 一个「自我检查后再交付」的智能体，与「输出即交付」的智能体，质量差距是数量级的。

## 验证循环不是额外开销

常见误区：认为验证是「浪费 token 的多余步骤」。

- 反例：一个不验证的智能体，交付了错误结果，人工审查/返工/事故处理成本远高于验证成本；
- 正解：**验证是保证智能体产出价值的必要投入**，不是可选项；
- 原则：宁可多一轮验证，不可少一次确认。

## 设计原则与思考

### 1. 确定性优先，语义性兜底

- 能用测试、Linter、类型检查解决的，绝不用模型裁判（模型裁判慢且贵）；
- 确定性验证覆盖不了的部分，才上视觉/模型裁判。

### 2. 验证结果要回传给模型

- 验证不只是「通过/失败」的判定，更是**反馈回路**：
- 失败 → 把验证失败详情给模型 → 模型修正 → 再验证（循环）；
- 这正好与编排循环（模块 1）融为一体。

### 3. 裁判要独立

- 裁判智能体与主智能体上下文隔离，避免「共谋式」自我认可；
- 裁判要有明确的评估标准（评分卡），而不是泛泛「你觉得怎么样」。

### 4. 验证要可观测

- 每次验证的输入、结果、修正次数都留痕；
- 这是「智能体可信度」的证据链。

## 常见问题

### Q：所有输出都要验证吗？

按风险分级：低风险（闲聊、草稿）轻验证或跳过；中风险（代码、数据）规则验证；高风险（支付、外发、生产变更）全链路验证 + 人在环上确认。

### Q：验证失败怎么办？

进入修正循环：反馈给模型 → 修正 → 重验。达到重试上限仍失败，则如实交付「未验证通过」状态或中断请求用户介入——绝不能把未验证的结果伪装成已验证。

## 小结

| 维度 | 要点 |
| --- | --- |
| 角色 | 生产级 vs 玩具级的分水岭 |
| 三种方式 | 规则反馈（测试/Linter/类型检查）/ 视觉反馈（截图）/ 模型裁判 |
| 硬数据 | 验证机制让输出质量提升 2-3 倍 |
| 定位 | 必要投入，不是额外开销 |
| 原则 | 确定性优先、失败回传修正、裁判独立、结果可观测 |
