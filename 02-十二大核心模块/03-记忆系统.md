# 模块 3：记忆（Memory）

## 一句话定位

**记忆是智能体跨越时间尺度、保持任务连续性的关键**——它让智能体不再像鱼一样只有七秒记忆，能在多轮对话与跨会话任务中保持上下文一致。

## 为什么需要记忆系统？

裸 LLM 无状态：每次调用相互独立，不记得上一次说过什么。没有记忆系统，智能体会出现三类典型故障：

1. **多轮脱节**：用户在第三轮引用第二轮的信息，模型已「失忆」；
2. **重复劳动**：长任务中重复做已经完成过的步骤；
3. **自相矛盾**：前后决策冲突，推翻自己早先的结论。

记忆系统就是对抗「鱼的记忆」的档案库。

## 记忆的时间维度：短期 + 长期

Harness 的记忆体系**不是单一存储**，而是在多个时间维度同时运作：

| 维度 | 内容 | 生命周期 | 作用 |
| --- | --- | --- | --- |
| **短期记忆** | 单次会话内的对话历史 | 随会话结束而结束 | 记录当前任务的所有交互信息，确保多轮对话不脱节 |
| **长期记忆** | 跨会话持久化的知识 | 持久保存，重启不丢 | 保留之前的任务进度、决策记录、用户偏好、领域知识 |

## 三大框架的长期记忆实现对比

| 框架 | 实现方式 | 特点 |
| --- | --- | --- |
| **Anthropic** | `claude.md` 项目文件 + 自动生成的 `MEMORY.md` | 以人类可读的文件形式持久化，天然可版本管理、可人工审阅 |
| **LangGraph** | 按命名空间组织的 JSON 存储 | 结构化、可按作用域（线程/会话/全局）隔离记忆 |
| **OpenAI** | 基于 SQLite 或 Redis 的会话存储 | 兼顾性能与稳定性，适配服务端部署 |

> 设计要点：长期记忆的实现要与「检查点」（模块 7）配合——记忆决定「记住什么」，检查点决定「进度恢复到哪」。

## 行业标杆：Claude Code 的三级记忆层级

Claude Code 的记忆设计被称为行业标杆，它把记忆拆成三个层级，对应不同访问成本：

| 层级 | 载体 | 单条规模 | 访问方式 | 定位 |
| --- | --- | --- | --- | --- |
| **第一层：轻量级索引** | 常驻内存 | 约 150 字符 | 即时 | 快速响应，随时可用 |
| **第二层：详细主题文件** | 磁盘上的结构化文件 | 按需加载 | 需要时加载 | 平衡容量与速度 |
| **第三层：原始交互记录** | 完整日志 | 大 | 仅通过搜索访问 | 保证数据完整性，供回溯审计 |

### 为什么是三级而不是一级？

- 全部常驻内存：容量不够（上下文窗口有限）；
- 全部按需加载：常用信息每次都检索，太慢；
- 三级结构 = 操作系统「寄存器/缓存/磁盘」的经典分层，用访问频率换速度与容量。

## 核心设计原则：记忆是提示，不是事实

> 智能体不会完全依赖记忆，而是将记忆作为一种**提示**，行动前会与**实际状态核对验证**，避免因记忆错误导致任务失败。

这是记忆系统最重要的设计原则，包含两层含义：

1. **记忆不是权威事实**：记忆可能过期、可能冲突、可能不完整；
2. **用之前先验证**：比如记忆说「该项目用 Python」，行动前先看一遍实际文件再下结论——把记忆当线索，不当结论。

### 为什么必须这样？

- 记忆是「被写下来的过去」，过去≠现在：文件可能被改、配置可能变了、用户可能改主意；
- 盲目信任记忆 = 拿过期的地图导航，必然翻车；
- 「记忆提示 + 现场核对」的模式，把记忆从「错误源」降级为「加速器」。

## 常见问题与思考

### Q1：短期记忆和上下文管理（模块 4）是什么关系？

短期记忆是「内容」，上下文管理是「策略」。对话历史是短期记忆的原始素材，但塞多少、压缩多少、屏蔽什么，由上下文管理模块决定。两者配合：记忆提供原始数据，上下文管理做裁剪优化。

### Q2：长期记忆要不要让用户可见、可编辑？

强烈建议。Claude Code 用 `MEMORY.md` 这类人类可读文件的意义就在于此：用户可以审阅、修正、删除记忆。不可见的记忆 = 不可控的智能体行为。

### Q3：记忆冲突怎么办？

设计上要有冲突处理策略：新记忆覆盖旧记忆、按时间戳裁决、或把冲突暴露给用户确认。任何「静默覆盖」都可能丢失重要上下文。

## 小结

| 维度 | 要点 |
| --- | --- |
| 角色 | 跨时间尺度的连续性保证 |
| 结构 | 短期（会话内）+ 长期（跨会话） |
| 标杆 | Claude Code 三级层级：索引 / 主题文件 / 原始记录 |
| 核心原则 | 记忆是提示不是事实；行动前先核对实际状态 |
| 常见坑 | 盲信记忆、记忆不可见、冲突静默覆盖 |
