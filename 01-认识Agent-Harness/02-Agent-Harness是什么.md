# Agent Harness 是什么？

## 一句话定义

**Agent Harness 就是包裹大语言模型的一整套「操作系统级」软件基础设施。**

它把一个只会输出文本、无状态、容易出错的**裸大语言模型**，变成一个**有目标、会用工具、能纠错、可持久运行**的**靠谱智能体**。

## 从「模型」到「智能体」的四重跃迁

裸 LLM 本质上只做一件事：根据输入预测下一个 token。要成为生产可用的智能体，需要 Harness 补齐四种能力：

| 裸 LLM 的缺陷 | Harness 补齐的能力 |
| --- | --- |
| 只会输出文本 | **有目标**：把用户需求转成可执行的任务，判断何时该做什么 |
| 无状态（每次调用相互独立） | **会用工具**：通过标准 Schema 调用外部能力，与现实世界交互 |
| 容易出错（幻觉、推理偏差） | **能纠错**：错误分类、重试、验证循环、护栏拦截 |
| 一次对话结束即结束 | **可持久运行**：状态保存、检查点、断点续跑、长任务管理 |

## 那句被行业奉为经典的话

> 「如果你不是模型，你就是 Harness。」
> —— LangChain 的维韦克·特里维迪（Vivek Trivedy）

这句话道破了核心本质：

- 在一个 AI 应用里，**只有「生成 token 的神经网络」这一部分是模型**；
- 其余所有东西——提示词怎么组装、上下文怎么管理、工具怎么调用、错误怎么处理、状态怎么保存——**全都是 Harness**。

## 一个关键认知：搭建智能体 ≠ 创造会思考的 AI

很多人以为「搭智能体」是在创造一个会思考的 AI。**这是误解。**

真实情况是：

> 我们日常说的搭建一个智能体，本质上**从来不是**创造一个会思考的 AI，而是**搭建一套 Harness，再把它对接给模型**。

思考能力来自模型（甚至来自模型与 Harness 的联合设计），而「让思考能落地成行动、能扛住真实环境」的能力，全部来自 Harness。

## 为什么说是「操作系统级」？

「操作系统」这个定语不是修辞，而是准确的类比：

- 操作系统管理 CPU、内存、硬盘、外设，让它们协同工作；
- Harness 管理模型推理、上下文、工具、记忆、状态、安全，让它们协同工作；
- 没有操作系统的裸机几乎无法使用；没有 Harness 的裸模型同样几乎无法用于生产。

## 容易混淆的边界

需要澄清一个常见误解：

> 很多人误以为 Harness 只是给提示词套个壳。

这是完全错误的认知。**Harness 不是简单的包装**，而是一套让自主智能体实现**自主思考、自主行动、自主修复**的完整系统，包含工具编排、状态持久化、错误恢复、验证循环、安全管控、生命周期管理等全套应用基础设施。

## 为什么「无状态」是核心问题？

展开理解「无状态」的危害：

- LLM 每次 API 调用都是独立的，不记得上次说过什么；
- 多轮对话的连续性完全依赖外部把历史塞回输入；
- 一旦历史丢失、截断或顺序错乱，智能体立刻「失忆」；
- 长任务中，模型甚至会因为看不到早先的决策而重复劳动、自相矛盾。

Harness 的记忆与状态模块，就是用来对抗这种「鱼的记忆」。

## 玩具 Demo 与生产级智能体的本质区别

| | 玩具级 Demo | 生产级智能体 |
| --- | --- | --- |
| 环境 | 受控、干净、单轮 | 真实、嘈杂、长程 |
| 错误 | 假设不会出错 | 假设一定会出错，并设计兜底 |
| 状态 | 无需保存 | 检查点 + 断点续跑 |
| 验证 | 人工看一眼 | 自动化验证循环 |
| 安全 | 不设防 | 输入/输出/工具三层护栏 |
| 可观测 | 无 | 可回溯、可调试 |

## 小结

- **Harness = 包裹 LLM 的操作系统级基础设施**；
- 智能体的能力上限由模型决定，**稳定性下限由 Harness 决定**；
- 从裸模型到智能体的每一步，都是 Harness 的职责。
