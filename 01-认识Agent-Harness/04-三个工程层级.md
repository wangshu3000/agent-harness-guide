# 三个工程层级：提示工程、上下文工程、Harness 工程

## 为什么必须先分清这三个层级？

在拆解 Harness 之前，必须先理清三个容易混淆的工程层级。它们层层递进，经常被混为一谈——很多人把「调提示词」当成在做 Harness，这是理解 Agent 工程的第一道分水岭。

## 三个层级的定义

| 层级 | 关注对象 | 核心问题 | 一句话概括 |
| --- | --- | --- | --- |
| **提示工程**（Prompt Engineering） | 模型接收的**指令内容** | 怎么让模型更精准地理解需求 | 解决「**说什么**」 |
| **上下文工程**（Context Engineering） | 模型**能看到哪些信息** | 怎么避免信息过载、防止上下文腐烂 | 解决「**看什么**」 |
| **Harness 工程** | 围绕模型运行的**整套系统** | 怎么让智能体稳定、可纠错、可持久地完成任务 | 解决「**怎么跑**」 |

## 第一层：提示工程

- **做什么**：打磨指令文本——系统提示词、任务描述、few-shot 示例、角色设定；
- **目标**：让模型更精准地理解需求，输出更符合预期的内容；
- **边界**：它只影响「模型这次推理读到的指令」，不关心模型之外发生了什么；
- **局限**：提示词写得再好，也无法解决工具调用失败、上下文爆炸、任务中断恢复等问题。

## 第二层：上下文工程

- **做什么**：管理模型在不同阶段能看到哪些信息——哪些该带上、哪些该压缩、哪些该检索、哪些该屏蔽；
- **目标**：在信息不足与信息过载之间找到平衡，避免模型被垃圾信息干扰、被超长上下文拖垮；
- **背景**：这个层级近年被重视，正是因为「上下文腐烂」成为生产级智能体的头号杀手（详见《上下文管理》模块）；
- **边界**：它管「信息流」，但不管工具怎么执行、错误怎么恢复、状态怎么保存。

## 第三层：Harness 工程（涵盖前两者）

Harness 工程是**最上层、最完整**的一层，它：

- **涵盖**提示工程（负责提示词组装策略）与上下文工程（负责上下文管理策略）；
- **更囊括**以下全套应用基础设施：

| 基础设施 | 职责 |
| --- | --- |
| 工具编排 | 工具注册、Schema 校验、沙箱执行、结果回传 |
| 状态持久化 | 检查点、断点续跑、任务进度保存 |
| 错误恢复 | 错误分类、重试、降级、中断等待人工 |
| 验证循环 | 规则验证、视觉验证、模型裁判 |
| 安全管控 | 输入/输出/工具三层护栏、权限决策 |
| 生命周期管理 | 初始化、循环执行、终止条件、清理回收 |

## 常见误区：Harness 不是「给提示词套个壳」

很多人以为 Harness = 提示词 + 模板 + 循环调用，这是**完全错误的认知**：

- 提示词组装只是 Harness 十二大核心模块之一（Prompt Assembly）；
- 如果 Harness 只是套壳，那它无法回答这些问题：
  - 工具调用失败了怎么办？（错误处理）
  - 上下文快爆了怎么办？（上下文管理）
  - 任务跑了一半崩溃了怎么办？（状态与检查点）
  - 模型要调一个危险操作怎么办？（护栏）
  - 怎么确认任务真的完成了？（验证与反馈）

## 为什么要强调「自主思考、自主行动、自主修复」？

Harness 不是静态包装，而是一套让自主智能体完整运转的系统：

- **自主思考**：模型在编排循环中自己决定下一步做什么（是否调工具、调哪个工具）；
- **自主行动**：工具层负责把思考落地为真实操作；
- **自主修复**：错误处理 + 验证循环让智能体发现错误后自我修正，而不是失败即终止。

## 玩具 Demo 与生产级智能体的本质区别

| 维度 | 玩具级 Demo | 生产级智能体 |
| --- | --- | --- |
| 层级 | 往往只做了提示工程 | 完整三层：提示 + 上下文 + Harness |
| 错误假设 | 假设模型一次成功 | 假设每一步都可能失败，并设计兜底 |
| 上下文 | 不管理，塞满为止 | 压缩、屏蔽、检索、委派 |
| 状态 | 无 | 检查点、可恢复 |
| 安全 | 无 | 多层护栏 |
| 验证 | 人工检查 | 自动化验证循环 |

## 三层级的演进关系

1. 先用**提示工程**拿到「能用的 Demo」；
2. 再补**上下文工程**，让模型在长对话、大信息量下不跑偏；
3. 最后补**Harness 工程**，让系统在生产环境稳定、可恢复、可信赖。

> 越往上层，越接近「系统」而非「文案」——这也是为什么 Harness 工程是 AI 工程化的核心硬骨头。

## 小结

- 三层级不是并列的三个技巧，而是**从局部到整体、从内容到系统**的递进；
- 判断一个团队处在哪个阶段：看它是在调 prompt，还是在管 context，还是在建 Harness；
- 生产级智能体的门槛，就在第三层。
