# 框架 1：Anthropic Claude Agent SDK

## 一句话定位

**薄 Harness 哲学的极致代表**——核心是信任模型、简化框架，用最薄的运行时承接最强的模型。

## 设计哲学

- **信任模型**：默认模型能把事情想对、做对，Harness 不抢模型的活；
- **简化框架**：能省则省，运行时保持极简；
- **与模型深度耦合**：为自家 Claude 模型量身设计，模型能力与 Harness 设计互相成就。

## 核心机制

### 1. 智能体循环：query() 函数

- 通过 `query()` 函数创建智能体循环——一个入口、一个循环，极简 API；
- 开发者不需要手写 while 循环，框架内部替你完成「组装→推理→执行→观察」的循环管理。

### 2. 运行时：极简的笨循环

- 呼应「笨循环（dumb loop）」理念：运行时只负责转场与调度，不参与推理；
- 遵循 **Gather-Act-Verify（收集→执行→验证）** 流程：
  - **Gather**：收集完成任务所需的信息（检索、读文件、查资料）；
  - **Act**：基于收集的信息执行动作（写文件、跑命令）；
  - **Verify**：验证动作结果是否正确（测试、检查），不对就修正。

### 3. 状态管理：Git 提交

- 用 **Git 提交**作为状态检查点（详见模块 7）；
- 任务里程碑自动提交，崩溃/中断后可恢复；
- 附带收益：可 diff、可回溯、可审计。

### 4. 多智能体：三种模式

| 模式 | 机制 |
| --- | --- |
| **Fork** | 创建父上下文的精确副本，子任务独立推进 |
| **Teammate** | 通过独立终端面板通信，并行协作 |
| **Worktree** | 每个 Agent 分配独立 Git 工作树，代码空间隔离 |

## 优点

- **轻量**：API 简单、心智负担低，几分钟能跑通；
- **高效**：运行时极简，没有多余抽象，性能开销小；
- **深度耦合**：Claude 模型的工具调用、长上下文能力与 Harness 无缝配合。

## 局限与思考

- **模型绑定**：深度优化面向 Claude，换模型可能吃不到全部红利；
- **控制力让渡**：信任模型的哲学意味着「流程显式控制」较弱——如果你需要锁死流程、严格分支，它的图式表达能力不如 LangGraph；
- **适用判断**：当「模型能力强 + 需要快速落地 + 接受模型自主决策」时，薄 Harness 是正确选择。
