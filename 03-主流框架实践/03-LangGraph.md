# 框架 3：LangGraph

## 一句话定位

**从 LangChain 进化而来的显式图结构框架**——把 Harness 建模为状态图，用节点和边精确锁死流程，主打显式流程控制与可调试性。

## 设计哲学

- **显式流程控制**：流程长什么样，图就是什么样——一切可预测、可检查；
- **可调试性**：节点级调试、状态可回溯，甚至支持时光倒流式重放；
- **适合复杂长流程**：多分支、条件流转、嵌套子任务的场景是它的主场。

## 核心机制

### 1. 图结构：Harness 即状态图

LangGraph 将 Harness 建模为**显式状态图**（State Graph）：

- **节点（Node）**：流程中的处理单元；
- **边（Edge）**：节点之间的流转；
- **条件边（Conditional Edge）**：根据状态动态决定下一步走向。

### 2. 最小骨架：llm_call + tool_node

一个基础的 LangGraph 智能体通常由两个节点 + 一条条件边构成：

```
         ┌──────────────────────────────┐
         │         llm_call 节点          │
         │   （调用大模型，输出决策）        │
         └──────────────┬───────────────┘
                        │ 条件边：有无工具调用？
           ┌────────────┴────────────┐
           ▼                         ▼
    tool_node 节点              结束（输出结果）
   （执行工具，结果回填）
           │
           └──────────→ 回到 llm_call
```

- **llm_call 节点**：调用大模型，产出文本或工具调用决策；
- **tool_node 节点**：执行工具、捕获结果、回填状态；
- **条件边**：判断「有没有工具调用」——有则进 tool_node，无则终止输出。

### 3. 状态管理：类型化字典 + 归约器 + 检查点

- **类型化字典**：状态结构显式声明（TypedDict），字段类型一目了然；
- **归约器（Reducer）**：状态更新按规则合并，而非简单覆盖（如「累加记录」或「保留最新」）；
- **检查点**：在超级步骤（superstep）边界触发保存；
- **时光倒流调试**：可回退到任意检查点，重放不同路径，定位问题。

### 4. 多智能体：嵌套状态图

- 子 Agent 实现为**嵌套状态图**：主图的一个节点内部是一张完整子图；
- 通过图结构管理任务流转，层次清晰、职责分明。

## 优点

- **流程锁死**：任何分支、循环、并行都在图里显式可见，不会「跑飞」；
- **可调试性极强**：节点级状态、检查点回放，复杂系统的排障能力是最大优势；
- **状态可控**：类型化 + 归约器，状态演化有规则可循；
- **生态成熟**：继承 LangChain 的工具与集成生态。

## 局限与思考

- **学习曲线陡**：要理解图 DSL（节点、边、条件边、归约器、superstep），心智负担高；
- **简单任务过重**：一个简单问答也用图建模，属于杀鸡用牛刀；
- **开发速度**：比代码优先框架（OpenAI SDK）慢——每一步流程都要显式建模；
- **适用判断**：当「流程复杂、分支多、失败代价高、需要严格可调试」时，显式图的价值完全覆盖成本。
